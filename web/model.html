Feature importance

Mostly: is the bus ahead already late?

The lag of the last three trips carries 60% of the regressor's importance, and peak hour adds 23%. That makes sense for a corridor, but it is also the feature to watch for leakage.

Honest caveats

Read before you quote a number.

These limits are part of the result. They also set the roadmap: each one has a matching next step.

Data

The telemetry is generated.

All 4,800 pings come from a 30-day simulation of one bus on one corridor, notebook 01, seed 42. Real AIS-140 traffic will be noisier, and the metrics above should be expected to move.

Leakage

Ablation without GPS speed.

gps_speed_kmh can leak the target, because a slower ping is partly the delay itself. The same regressor, seed 42, days 1–24 / 25–30, trained without that feature:

Calibration

Coverage is measured on synthetic days.

The window is centred on the point delay, with a 0.6 min minimum half-width and a 1.35× peak stretch. On held-out days 25–30 it covers … of actual delays (peak …, off-peak …). That is not a guarantee for live traffic.

Scope

One corridor, one bus.

NH-44 Jalandhar → Phagwara, 6 stops, 21.2 km. Other routes, buses and operators are on the roadmap, not in this model.
